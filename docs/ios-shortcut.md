# iOS 捷徑：從 104 分享直接新增投遞

在 104 App（或 Safari 的 104 職缺頁）按「分享」→ 選這個捷徑，就會打開新增表單，並帶入公司、職稱、職缺連結與來源。

## 為什麼用捷徑

104 會封鎖雲端主機的 IP（Vercel 美國、香港機房都回 403），所以 App 的伺服器查不了 104；瀏覽器裡的網頁又會被 CORS 擋。捷徑用**手機自己的網路**呼叫 104，再透過[網址參數預填](features.md#用網址開啟新增表單預填)把結果交給 App，App 這邊不需要後端。

查詢用的是 104 職缺頁背後的非官方 JSON 介面：把職缺連結的 `/job/` 換成 `/job/ajax/content/` 就是它的網址。104 改版時可能失效；查不到時表單還是會打開並帶入連結，公司和職稱自己填即可。

捷徑只負責把 104 回傳的 `data.header` 原樣轉給 App（`h104` 參數），由 App 取出公司與職稱，所以只需要 7 個動作。**這個捷徑只用於 104 連結**；Cake、LinkedIn 請直接在 App 裡貼上連結。

## 建立步驟

在「捷徑」App 按右上角「＋」建立新捷徑，取名例如「存到投遞追蹤」。

> **找動作**：各 iOS 版本的中文名稱不太一致，下面以英文名稱為準、中文僅供參考。找不到時在動作搜尋欄試英文名稱或中文關鍵字（例如「取代」「辭典」「編碼」）。
>
> **不用設定變數**：每個動作會自動接收上一個動作的結果，照順序加入就好。只有第 6 步要手動插入第 1 步的結果。
>
> **變數不能自己打字**：「捷徑輸入」「URL」這類變數要從鍵盤上方的變數列點選，會顯示成**藍底、前面有圖示的標籤**。自己打出同樣的字只是一般文字，捷徑不會把它當成變數，後面就會出錯。

### 0. 讓捷徑出現在分享選單

點捷徑名稱旁的 ⓘ（或底部的「詳細資訊」），開啟「**在分享表單中顯示**」。最上方會出現「從分享表單接收 … 」：

- 點接收類型，全部取消後**只勾「URL」和「文字」**。勾成其他類型（例如「App 和其他 2 個」）時，104 分享的內容可能收不到，捷徑會改讀剪貼簿。
- 「若沒有輸入」改成「**取得剪貼簿內容**」，這樣也能先複製 104 連結、再從主畫面執行捷徑。

### 1～7. 依序加入動作

| # | 動作（英文名稱） | 要設定的地方 |
|---|---|---|
| 1 | **Get URLs from Input**（取得 URL） | 輸入是藍色的「**捷徑輸入**」變數（通常已自動帶入；不是的話點那一格，從變數列選） |
| 2 | **Replace Text**（取代文字） | 尋找 `/job/`，取代為 `/job/ajax/content/` |
| 3 | **Get Contents of URL**（取得 URL 的內容） | 不用改。（若 104 開始拒絕查詢，展開「標頭」新增鍵 `Referer`、值 `https://www.104.com.tw/`） |
| 4 | **Get Dictionary Value**（取得辭典值） | 取得「值」，鍵填 `data.header` |
| 5 | **URL Encode**（URL 編碼） | 不用改 |
| 6 | **Text**（文字） | 輸入 `https://你的網域/applications?new=1&h104=`，接著插入變數「**URL 編碼的文字**」（第 5 步），再輸入 `&url=`，接著插入變數「**URL**」（第 1 步；在鍵盤上方的變數列找，或長按選「選取魔術變數」） |
| 7 | **Open URLs**（打開 URL） | 不用改 |

第 6 步完成後看起來像：

```
https://你的網域/applications?new=1&h104=[URL 編碼的文字]&url=[URL]
```

`你的網域` 換成部署後的網址。`url` 要放在最後面。

### 想用 Chrome 開啟

第 7 步會用系統的預設瀏覽器開啟。想固定用 Chrome，把第 6 步開頭的 `https://` 改成 `googlechromes://`：

```
googlechromes://你的網域/applications?new=1&h104=[URL 編碼的文字]&url=[URL]
```

這樣會在 **Chrome 的分頁**打開表單（Chrome 要先登入過一次），**不會打開主畫面上的 App**，原因見下方「第一次使用」。

### 想在主畫面 App 裡新增（剪貼簿）

捷徑無法打開主畫面 App，但可以把預填網址拷貝到剪貼簿，再由 App 讀取：

1. 把第 7 步的 **Open URLs** 換成 **Copy to Clipboard**（拷貝到剪貼簿），輸入是第 6 步的文字。
2. 想讓捷徑順便打開 App 的話，在後面加 **Open App**（打開 App），看清單裡選不選得到你的主畫面 App；選不到就自己點開。
3. 在 App 的投遞頁按「**從剪貼簿新增**」（手機版是「新增投遞」左邊的剪貼簿圖示），iOS 跳出「貼上」時按下去，就會打開預填好的表單。

這種用法只讀網址參數，所以第 6 步的網域就算沒改也能用。剪貼簿裡如果只是一般的職缺連結（例如在 104 按「拷貝連結」），按「從剪貼簿新增」也會帶入連結與來源。

## 第一次使用

- 第一次執行到第 3 步時，iOS 會詢問是否允許捷徑連線到 `www.104.com.tw`，選「**永遠允許**」。
- 第 7 步會用**預設瀏覽器**（通常是 Safari）開啟，**不會打開主畫面上的 App**：直到 iOS 26，iOS 都不支援把連結交給已加入主畫面的網頁 App。用 Chrome 加入主畫面也一樣，iOS 上的主畫面網頁 App 都跑在系統的 WebKit 上。
- 瀏覽器和主畫面 App 的登入狀態是分開的（加入主畫面時只會複製一次當下的登入 cookie）。
  - 建議順序：**先在瀏覽器開啟網站並登入，再加入主畫面**，兩邊就都是登入狀態。
  - 在瀏覽器新增的投遞會即時同步到主畫面 App，存完可以直接關掉分頁。
  - 瀏覽器沒登入的話會被導到登入頁，這一筆的預填內容不會保留。

## 疑難排解

| 狀況 | 可能原因 |
|---|---|
| 表單有連結，但公司和職稱是空的 | 104 改了 JSON 格式或拒絕查詢。在第 3 步後加「Quick Look（快速查看）」看回應內容；或第 4 步取不到值，把鍵改成連續兩個 Get Dictionary Value：`data` → `header` |
| 第 3 步出現「確定傳送一個有效 URL…」 | 第 1 步沒取到連結。在第 1 步前加「Quick Look（快速查看）」看「捷徑輸入」：顯示「沒有項目」時，檢查第 1 步的輸入是不是**藍色變數**（不是自己打的字）、接收類型有沒有勾「URL」和「文字」，以及是不是從分享選單執行 |
| 第 3 步出現其他錯誤 | 手機沒網路、沒允許捷徑連線到 104，或分享的不是 104 職缺連結 |
| 沒有跳出表單、只看到看板 | 網址少了 `new=1`，或第 6 步的網址打錯 |
| 跳到登入頁 | 開啟表單的瀏覽器還沒登入，見上方「第一次使用」 |
| 分享選單裡找不到這個捷徑 | 第 0 步的「在分享表單中顯示」沒開；iOS 26 的分享選單會先收起部分項目，往下捲或點「編輯動作」把它加到前面 |
