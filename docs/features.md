## 投遞管理

- **看板與列表**：看板依狀態分欄（想投、已投遞、面試中、Offer、未錄取、已撤回）。「未錄取」是公司拒絕，「已撤回」是自己放棄（撤回履歷、婉拒面試等），兩者都不會出現在提醒裡。手機上看板改成上方的狀態切換鈕，一次顯示一欄，列表改成堆疊卡片，都不需要橫向捲動；平板與電腦維持多欄與表格。
- **搜尋與篩選**：可搜尋公司、職位、備註、履歷版本，並依月份、來源篩選。檢視模式、搜尋、月份、來源與手機版的狀態都存在網址（`?view=list&q=...&month=2026-10&source=...&status=interview`），重新整理或分享連結都會保留；不合法的值會被忽略。網址沒有指定檢視時，用這台裝置上次選的看板或列表。
- **月份**：依「投遞日」所在月份；沒有投遞日的項目（例如「想投」）改用建立日的月份。下拉選單只列出資料裡有出現的月份，新的在前。月份篩選只影響看板與列表，摘要卡片、提醒清單與統計仍以全部資料計算。
- **新增與編輯**：欄位包含公司、職位、職缺連結、來源、狀態、投遞日、下次跟進日、面試時間與地點、履歷版本、備註。
  - 面試時間與地點只在狀態是「面試中」時出現；已經填過的話，改成其他狀態也會保留並顯示在表單裡。
  - 面試地點可以寫地址、貼地圖或視訊會議連結，也可以混在一起寫（例如「台北市信義區 5F https://maps.apple/…」）。
- **面試資訊**：「面試中」的卡片與列表會顯示面試時間（例如「11/02（一）15:00」）與地點；地點裡的連結依網域變成「地圖」「視訊會議」或「連結」按鈕。資料庫欄位見 `0004_interview.sql`。
  - 有改動就關閉表單時，會先確認是否放棄。
  - 刪除需要再按一次確認。
- **範例資料**：第一次使用時會顯示範例資料預覽版面，新增第一筆後自動消失，範例不會存進資料庫。

## 貼上職缺連結

在「職缺連結」欄位貼上連結（或整段分享訊息）時：

1. **擷取連結**：只保留訊息中的網址，例如 104 App 分享的「我在104工作快找上發現了…」整段文字，只會留下 `https://www.104.com.tw/job/xxxxx`。104 連結後面的追蹤參數（`?jobsource=ios_share`）會一併移除。
   - iOS 上從 104 App「分享 → 拷貝」時，說明文字和網址會存成剪貼簿裡的不同項目，Safari 給網頁的純文字只有說明文字。因此貼上時會一併從網址格式（`text/uri-list`）尋找連結。
2. **判斷來源**：104、Cake、LinkedIn 會自動選好「來源」；手動選過來源後，不會再被自動覆蓋。
3. **辨識 Cake 職缺**：貼上或離開欄位時，若是 Cake 職缺連結（`https://www.cake.me/companies/{公司}/jobs/{職缺}`，舊網域 cakeresume.com 也可）且公司或職位還沒填，會透過 `/api/cake-job-preview` 查出公司與職稱，只填入仍是空白的欄位。
   - 伺服器端讀 Cake 職缺頁的 JSON-LD（JobPosting），沒有的話用 og:title。
   - 只有登入的使用者能呼叫；試用模式不會呼叫 API，貼上 Cake 連結時改顯示「登入後貼上 Cake 連結，可自動帶入公司與職稱」；查詢網址由伺服器用驗證過的公司與職缺代碼自己組出，轉址只跟隨到 www.cake.me。
   - 查詢中、成功、失敗都會在欄位下方顯示提示；失敗時手動填寫即可。Cake 也在 Cloudflare 後面，若日後像 104 一樣封鎖雲端主機，Vercel Logs 會看到 `cake-job-preview: Cake 回應 403`。
   - 104 不支援：104 會封鎖雲端主機 IP（見下方），請改用 iOS 捷徑。

## 用網址開啟新增表單（預填）

開啟 `/applications?new=1&company=公司&title=職稱&url=職缺連結` 會直接跳出新增表單並帶入欄位，給 iOS 捷徑（設定方式見 [ios-shortcut.md](ios-shortcut.md)）、書籤小工具等外部工具使用。

- 一定要有 `new` 參數才會開表單；`company`、`title`、`url` 都可省略（只有 `?new=1` 就是開空白表單）。參數值記得用 `encodeURIComponent` 編碼。
- 也可以用 `h104` 參數傳入 104 職缺 JSON 的 `data.header`（整段 JSON 編碼後放進去），App 會取出 `custName`、`jobName` 當公司與職稱；同時有 `company`／`title` 時以後者為準。iOS 捷徑用這個方式，省掉在捷徑裡拆欄位。
- 公司、職稱會去除多餘空白並截到表單的長度上限；連結會比照貼上的處理（擷取網址、移除 104 追蹤參數、只接受 http(s)），來源由連結判斷。
- 讀完後會從網址拿掉這些參數，重新整理不會再開一次；其他篩選參數保留。
- 預填的內容沒有儲存就關閉時，會詢問是否放棄。
- 還沒登入時會被導到登入頁，預填內容不會保留。
- **從剪貼簿新增**：投遞頁的「從剪貼簿新增」按鈕（手機版是新增按鈕左邊的剪貼簿圖示）會讀取剪貼簿。內容是上述預填網址時照網址參數解析（不看網域），是一般的職缺連結或分享訊息時只帶入連結。iOS 會先跳出「貼上」確認；讀不到或沒有連結時會顯示提示。iOS 捷徑打不開主畫面 App，用這個方式把資料帶進去。試用模式不顯示這個按鈕（試用的訪客用不到捷徑）。

### 曾嘗試但已移除：自動辨識職缺

曾經做過「貼上 104 連結後自動查出公司與職稱」，由伺服器端 API 代為查詢 104 的非官方 JSON 介面。本機測試可行，但部署到 Vercel 後，104 不論美國或香港機房都回應 403，判斷是封鎖雲端主機的 IP，因此移除。

目前改由使用者自己的裝置查詢：[iOS 捷徑](ios-shortcut.md)用手機的網路呼叫 104，再把公司與職稱用上面的網址參數帶進新增表單。

## 提醒與跟進

- 超過 N 天（可設定 7／10／14／21／30）沒消息，或跟進日到了，會出現在「該跟進了」清單。
- 「N 天」的設定存在資料庫（`user_settings`），所有裝置共用；每台裝置也保留一份本機副本，離線時照常運作。資料庫還沒有設定時，會先用這台裝置目前的值。
- 一鍵複製跟進訊息、一鍵「已跟進」（記錄聯絡日並將下次跟進日設為 7 天後）。
- 摘要卡片顯示已投遞數、面試中數量、回應率與待處理提醒。

## 統計

各來源、各履歷版本的回應率（面試、Offer 或收到婉拒都算有回應）；筆數太少時會註明僅供參考。

## 帳號與資料

- **Google 登入**，登入頁獨立為 `/login`；未登入開啟任何頁面會導向登入頁，已登入開啟登入頁會導回投遞頁。
- **資料隔離**：每個帳號只能讀寫自己的資料，由資料庫的 Row Level Security 保證。匿名角色對資料表沒有任何權限。
- **跨裝置即時同步**：用 Supabase Realtime，手機改的資料電腦馬上更新；App 回到前景或恢復連線時自動補抓。
- **匯出與匯入**（在設定頁）：匯出 JSON（完整備份）或 CSV（可用試算表開啟）；匯入 JSON，單次最多 300 筆。

## PWA

- 可安裝到主畫面（iOS 請用 Safari 的「加入主畫面」）。
- 離線可看最近一次同步的資料；離線時新增與修改會被擋下並提示。
- Service Worker 安裝時預先快取投遞、統計、設定與登入頁、離線頁和圖示，離線或登入過期時也能開啟。
- App 圖示角標顯示待處理數量（瀏覽器支援時）。
