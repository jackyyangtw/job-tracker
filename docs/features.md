## 投遞管理

- **看板與列表**：看板依狀態分欄（想投、已投遞、面試中、Offer、已婉拒、已撤回）。手機上看板改成上方的狀態切換鈕，一次顯示一欄，列表改成堆疊卡片，都不需要橫向捲動；平板與電腦維持多欄與表格。
- **搜尋與篩選**：可搜尋公司、職位、備註、履歷版本，並依來源篩選。檢視模式、搜尋與來源會同步到網址（`?view=list&q=...&source=...`），重新整理或分享連結都會保留。
- **新增與編輯**：欄位包含公司、職位、職缺連結、來源、狀態、投遞日、下次跟進日、履歷版本、備註。
  - 有改動就關閉表單時，會先確認是否放棄。
  - 刪除需要再按一次確認。
- **範例資料**：第一次使用時會顯示範例資料預覽版面，新增第一筆後自動消失，範例不會存進資料庫。

## 貼上職缺連結

在「職缺連結」欄位貼上連結（或整段分享訊息）時：

1. **擷取連結**：只保留訊息中的網址，例如 104 App 分享的「我在104工作快找上發現了…」整段文字，只會留下 `https://www.104.com.tw/job/xxxxx`。104 連結後面的追蹤參數（`?jobsource=ios_share`）會一併移除。
2. **判斷來源**：104、Cake、LinkedIn 會自動選好「來源」；手動選過來源後，不會再被自動覆蓋。
### 曾嘗試但已移除：自動辨識職缺

曾經做過「貼上 104 連結後自動查出公司與職稱」，由伺服器端 API 代為查詢 104 的非官方 JSON 介面。本機測試可行，但部署到 Vercel 後，104 不論美國或香港機房都回應 403，判斷是封鎖雲端主機的 IP，因此移除。

若之後要再做，可行方向是讓查詢在使用者自己的裝置上執行，例如 iOS 捷徑（用手機的網路查詢，再把公司與職稱用網址參數帶進新增表單）。

## 提醒與跟進

- 超過 N 天（可設定 7／10／14／21／30）沒消息，或跟進日到了，會出現在「該跟進了」清單。
- 一鍵複製跟進訊息、一鍵「已跟進」（記錄聯絡日並將下次跟進日設為 7 天後）。
- 摘要卡片顯示已投遞數、面試中數量、回應率與待處理提醒。

## 統計

各來源、各履歷版本的回應率（面試、Offer 或收到婉拒都算有回應）；筆數太少時會註明僅供參考。

## 帳號與資料

- **Google 登入**，登入頁獨立為 `/login`；未登入開啟首頁會導向登入頁，已登入開啟登入頁會導回首頁。
- **資料隔離**：每個帳號只能讀寫自己的資料，由資料庫的 Row Level Security 保證。匿名角色對資料表沒有任何權限。
- **跨裝置即時同步**：用 Supabase Realtime，手機改的資料電腦馬上更新；App 回到前景或恢復連線時自動補抓。
- **匯出與匯入**：匯出 JSON（完整備份）或 CSV（可用試算表開啟）；匯入 JSON，單次最多 300 筆。

## PWA

- 可安裝到主畫面（iOS 請用 Safari 的「加入主畫面」）。
- 離線可看最近一次同步的資料；離線時新增與修改會被擋下並提示。
- Service Worker 安裝時預先快取首頁與登入頁、離線頁和圖示，離線或登入過期時也能開啟。
- App 圖示角標顯示待處理數量（瀏覽器支援時）。
